### 一、 核心概念纠偏：镜像 vs 容器

在 C++ 面向对象编程中：
* **类** 是静态的代码模板，躺在硬盘里什么都不干。
* **对象** 是用 `new` 在内存里跑起来的实例。

映射到 Docker 中：
* **镜像** = 类。它是一个静态的、只读的文件包（包含了操作系统环境、你的代码、依赖库等）。它躺在硬盘里，自己不会运行。
* **容器** = 对象。当你用命令把镜像“跑”起来时，它就变成了一个容器。容器是动态的，有进程，有内存，会执行任务。

**一句话总结：镜像是模板，容器是跑起来的实例。** 你可以基于同一个镜像，跑出成百上千个一模一样的容器。

### 二、 通俗比喻：为什么要用 Docker？

假设你要在 Linux 上部署 Redis。
* **传统做法（裸机安装）**：相当于你买了一个毛坯房。你要自己铺水管（装依赖）、拉网线（配网络）、刷墙（改配置）。如果下次你要装 MySQL，又得重新搞一遍，而且万一水管破了，还可能把别的房间淹了（依赖冲突）。
* **Docker 做法**：相当于你直接买了一个精装集装箱。里面 Redis、水管、网线、配置全都已经装好了。你只需要把这个集装箱“哐当”一声放在空地上，通上电，它就能立刻工作。不要了？叉车拉走，地上干干净净。

### 三、 Docker 极简命令手册（结合你的项目实战）

作为初学者，你只需要记住以下 6 组命令，就能玩转 90% 的日常开发。我们用你刚才部署的 MySQL 来举例：

#### 1. 拉取镜像 (下载精装集装箱图纸)
```bash
docker pull mysql:8.0
```
* `mysql` 是镜像名，`8.0` 是标签。如果不写标签，默认拉 `latest`（最新版，但生产环境不推荐用 latest，容易踩版本兼容的坑）。

#### 2. 运行容器 (按图纸造个房子并通电)
这就是你之前执行的那条长命令：
```bash
docker run -d --name chat-mysql -p 3306:3306 mysql:8.0
```
* `-d` (detach)：后台运行。如果没有它，你的终端会被日志占满，按 Ctrl+C 容器就死了。
* `--name`：给容器起个好记的名字。
* `-p 宿主机端口:容器端口`：端口映射。你的 C++ 代码连虚拟机的 3306，Docker 会把流量转发给容器内部的 3306。

#### 3. 查看状态 (看看哪些房子在运行)
```bash
docker ps
```
* 这个命令只显示**正在运行**的容器。
* 如果你想看所有容器（包括已经死掉的），用 `docker ps -a`。这在排查“为什么我的容器跑一下就没了”时非常有用。

#### 4. 查看日志 (看集装箱里的监控录像)
如果容器没跑起来，或者报错了，必须看这个：
```bash
docker logs chat-mysql
```
* 加上 `-f` 可以实时滚动跟踪日志：`docker logs -f chat-mysql`（相当于 Linux 的 `tail -f`）。

#### 5. 进入容器内部 (拿着钥匙进房子溜达)
有时候你想看看容器里的文件结构对不对，或者想在容器里敲 `mysql` 命令：
```bash
docker exec -it chat-mysql bash
```
* `exec`：在运行的容器中执行命令。
* `-it`：保持交互式终端（不加上这个你没法输入命令）。
* `bash`：你要执行的命令是启动 bash shell。
* 进去之后，你就像登入了一个极简版的 Linux 系统。输入 `exit` 退出（退出不会影响容器继续运行）。

#### 6. 停止、启动与销毁 (断电、通电、拆房子)
```bash
docker stop chat-mysql   # 停止运行（数据还在，下次还能 start）
docker start chat-mysql  # 重新启动
docker rm chat-mysql     # 彻底删除容器（房子拆了，但图纸还在）
```
* **注意：** `docker rm` 删除容器后，如果你没有用 `-v` 挂载数据卷，容器里的数据就全没了！这也是为什么之前部署 MySQL 时要加 `-v /mydata/mysql/data:/var/lib/mysql`，这相当于给集装箱里的保险柜接了一根管子到外面的仓库，即使集装箱拆了，保险柜还在。

### 四、 总结与下一步预告

现在你已经搞懂了基本概念和日常操作命令。针对你的目标 B（把 Node.js 和 C++ 也部署到 Linux 上），我们需要进入下一阶段的学习。

等你的项目代码写完后，我们会引入两个新概念：
1. **`Dockerfile`**：相当于你写一份“精装图纸说明书”（包含：拿个 Linux 基础环境 -> 把我的 C++ 代码拷进去 -> 装个 gRPC 库 -> 执行编译 -> 运行 exe）。有了它，你就能把自己的 C++ 服务也变成一个**镜像**。
2. **`Docker Compose`**：相当于一个“总调度员”。你写个配置文件，告诉他“启动 1 个 MySQL、1 个 Redis、1 个 Node.js、1 个 C++ Server，并且把它们 network 连通”。一条命令 `docker-compose up`，整个微服务集群瞬间启动。
