# P0 密码哈希改造

## 1. 文档目标

本文记录第一版项目中密码存储与校验链路的安全改造，重点回答以下问题：

- 原实现为什么不能继续用于密码存储。
- 为什么选择 libsodium 的 Argon2id。
- vcpkg 与 CMake 如何接入依赖。
- 注册、登录、重置密码分别怎么修改。
- 数据库和 Redis 如何处理旧数据。
- 当前方案解决了什么，没有解决什么。

本次改造基于 `feature/优化迭代` 分支，对应提交：

- `security(config): remove tracked credentials`
- `security(auth): hash passwords with Argon2id`

libsodium、vcpkg、CMake 和 API 的独立使用说明见：

[libsodium-Argon2id使用指南.md](./libsodium-Argon2id使用指南.md)

## 2. 原问题

改造前，客户端在发送密码前执行 `xorString`：

```cpp
json_obj["passwd"] = xorString(password);
```

`xorString` 使用字符串长度作为 XOR 密钥，服务端收到的值虽然不是原始密码，但存在以下问题：

1. 变换算法公开且可逆，不构成加密。
2. 长度相同、字符分布相同的密码存在明显规律。
3. 数据库保存的仍然是可直接恢复的口令材料。
4. 登录时直接比较字符串，不具备密码哈希的抗暴力破解能力。
5. 多个服务会读取并携带 `pwd`，扩大了敏感数据暴露面。
6. 注册、登录和重置响应曾经回显密码、验证码等字段。
7. 日志中曾经出现完整请求体、密码和配置键值。

密码安全的目标不是“让密码看起来不是明文”，而是：

- 数据库泄露后不能直接恢复用户密码。
- 同一密码在不同用户之间不能得到相同哈希。
- 校验过程应使用成熟的、抗 GPU/ASIC 的密码哈希算法。
- 业务服务不能通过普通查询读取密码哈希。

## 3. 为什么选择 Argon2id

本次采用 libsodium 提供的 Argon2id。

选择原因：

- Argon2id 是当前推荐的密码哈希算法之一。
- libsodium 封装了参数编码、盐生成、校验和常量时间比较。
- 不需要手写盐、迭代次数、内存参数和哈希组合格式。
- vcpkg 中已有 `libsodium 1.0.22` 端口。
- CMake 集成简单，不需要 OpenSSL 级别的额外配置。

本项目使用 libsodium 的交互式参数：

```cpp
crypto_pwhash_OPSLIMIT_INTERACTIVE
crypto_pwhash_MEMLIMIT_INTERACTIVE
```

它们适合普通登录页面。libsodium 会把算法、版本、盐、参数和最终哈希编码为字符串，因此数据库只需要保存这一整串结果。

## 4. vcpkg 与 CMake 接入

### 4.1 安装依赖

在仓库根目录执行：

```powershell
C:\vcpkg\vcpkg.exe install libsodium:x64-windows
```

安装后会提供：

```text
include/sodium.h
include/sodium/...
lib/libsodium.lib
debug/lib/libsodium.lib
debug/bin/libsodium.dll
share/unofficial-sodium/unofficial-sodiumConfig.cmake
```

vcpkg 官方提示的 CMake 接入方式是：

```cmake
find_package(unofficial-sodium CONFIG REQUIRED)
target_link_libraries(target PRIVATE unofficial-sodium::sodium)
```

### 4.2 GateServer CMake

`PasswordHasher.cpp` 加入 `GATE_SERVER_SOURCES`：

```cmake
set(GATE_SERVER_SOURCES
    # ...
    PasswordHasher.cpp
)
```

查找并链接 libsodium：

```cmake
find_package(unofficial-sodium CONFIG REQUIRED)

target_link_libraries(GateServer PRIVATE
    # ...
    unofficial-sodium::sodium
)
```

只有 GateServer 处理注册、登录和密码重置，因此当前不需要让两个 ChatServer 链接 libsodium。

### 4.3 运行目录 DLL

Debug 构建会自动把：

```text
C:\vcpkg\installed\x64-windows\debug\bin\libsodium.dll
```

复制到 GateServer 的运行目录。部署 Release 版本时需要确认对应的
`C:\vcpkg\installed\x64-windows\bin\libsodium.dll` 也在发布包中。

## 5. PasswordHasher 实现

新增文件：

```text
server/GateServer/PasswordHasher.h
server/GateServer/PasswordHasher.cpp
```

接口：

```cpp
class PasswordHasher {
public:
    static bool Hash(const std::string& password, std::string& encoded_hash);
    static bool Verify(const std::string& password, const std::string& encoded_hash);

private:
    static bool EnsureInitialized();
};
```

### 5.1 初始化

`sodium_init()` 只执行一次：

```cpp
std::call_once(init_flag, [] {
    initialized = sodium_init() >= 0;
});
```

返回负数时哈希接口返回失败，不允许继续使用未初始化的加密库。

### 5.2 生成哈希

```cpp
crypto_pwhash_str(
    hash.data(),
    password.data(),
    password.size(),
    crypto_pwhash_OPSLIMIT_INTERACTIVE,
    crypto_pwhash_MEMLIMIT_INTERACTIVE);
```

输出是类似下面的自描述字符串：

```text
$argon2id$v=19$m=65536,t=2,p=1$...salt...$...hash...
```

数据库不需要分别保存盐或参数，保存完整字符串即可。

### 5.3 校验密码

```cpp
crypto_pwhash_str_verify(
    encoded_hash.c_str(),
    password.data(),
    password.size()) == 0;
```

必须使用库提供的校验接口，不能自行拆出哈希后做普通 `==` 比较。

## 6. 具体修改流程

### 6.1 客户端不再 XOR

修改文件：

```text
client/logindialog.cpp
client/registerdialog.cpp
client/resetdialog.cpp
client/global.cpp
client/global.h
```

登录改为直接传递界面输入的密码：

```cpp
json_obj["passwd"] = pwd;
```

注册：

```cpp
json_obj["passwd"] = ui->pass_edit->text();
json_obj["confirm"] = ui->ack_edit->text();
```

重置密码：

```cpp
json_obj["passwd"] = ui->pwd_edit->text();
```

删除全局 `xorString`，避免后续代码继续误认为它提供加密能力。

当前 HTTP 链路只适合本机或受控内网演示。HTTPS 属于后续 P1，不应把“服务端哈希”误解成“网络传输已经加密”。

### 6.2 注册流程

GateServer 收到原始密码后：

1. 校验密码与确认密码一致。
2. 校验 Redis 中的邮箱验证码。
3. 调用 `PasswordHasher::Hash`。
4. 把 Argon2id 字符串传给 `reg_user` 存储过程。
5. 存储过程写入 `user.password_hash`。
6. 响应只返回 `error`、`uid`、`user` 和 `email`。

不再在响应中返回：

```text
passwd
confirm
verifycode
```

### 6.3 登录流程

GateServer 根据邮箱查询：

```sql
SELECT uid, name, email, password_hash
FROM user
WHERE email = ?;
```

随后调用：

```cpp
PasswordHasher::Verify(input_password, password_hash);
```

校验通过后，数据库层只返回 UID、用户名和邮箱，不把密码哈希继续传递到状态服务或聊天服务。

### 6.4 重置密码流程

重置密码同样先执行 Argon2id：

```sql
UPDATE user
SET password_hash = ?
WHERE name = ?;
```

响应中不再回显新密码和验证码。

### 6.5 ChatServer 去除密码字段

ChatServer 只负责在线会话和聊天，不需要读取密码哈希。

因此：

- 从 `ChatServer/data.h`、`ChatServer2/data.h` 的 `UserInfo` 删除 `pwd`。
- ChatServer 的 MySQL 查询使用明确字段列表，不读取 `password_hash`。
- ChatServer/Redis 用户缓存不再包含密码或密码哈希。
- ChatServer 聊天登录响应不再返回 `pwd`。
- 删除 ChatServer 中未使用的注册、改密和密码校验接口。

这体现了最小权限原则：聊天服务即使被攻击，也没有必要接触认证材料。

## 7. 数据库改造

新增文件：

```text
server/sql/schema.sql
server/sql/migrations/001_password_hash.sql
```

### 7.1 字段改名

原字段：

```sql
pwd VARCHAR(255) NOT NULL
```

新字段：

```sql
password_hash VARCHAR(255) NOT NULL
```

Argon2id 字符串通常小于 128 字节，`VARCHAR(255)` 足够。

### 7.2 存储过程

`reg_user` 的第三个参数改名为 `new_password_hash`，插入字段改为 `password_hash`。

`schema.sql` 包含完整表结构和存储过程，适合后续空库初始化。

`001_password_hash.sql` 包含现有库的一次性迁移，包括：

- `CHANGE COLUMN pwd password_hash`。
- 删除并重建 `reg_user`。

### 7.3 本次数据处理

由于现有数据允许重建，本次没有实现旧 XOR 密码的兼容迁移。

执行过程：

1. 使用 `mysqldump` 备份 `guisan`。
2. 执行字段迁移和存储过程重建。
3. 清空 `user`、`friend`、`friend_apply`。
4. 把 `user_id` 重置为 0。
5. 清理本项目 Redis key。

备份文件位于系统临时目录，不进入 Git。

## 8. Redis 改造

旧用户资料缓存包含 `pwd`，本次全部移除。

用户公开资料缓存只保留：

```text
uid
name
email
nick
desc
sex
icon
```

密码哈希只由 GateServer 在登录时读取，不写入 ChatServer 使用的公开资料缓存。

## 10. 当前边界

本改造解决的是密码存储和校验问题，不解决：

- HTTP 明文传输。
- 内部 gRPC 未启用 TLS/mTLS。
- 验证码发送频率限制。
- 登录失败频率限制。
- Token 有效期。
- 密码策略和泄露密码库检查。

这些属于后续 P1 安全与可靠性优化。

## 11. 面试可讲要点

可以按以下链条说明：

1. 原实现的 XOR 只是混淆，数据库泄露后可逆。
2. 改成服务端 Argon2id，密码不可逆保存。
3. 使用 libsodium 避免自行实现盐、参数编码和常量时间比较。
4. GateServer 独占认证材料，ChatServer 使用最小字段查询。
5. 通过 vcpkg 引入依赖，CMake 使用 `unofficial-sodium::sodium`。
6. 支持重建数据时采用破坏式迁移，避免保留不可信旧口令。
