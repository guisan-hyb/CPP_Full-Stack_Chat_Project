## json获取数据不同写法：

在日常开发中，最常用的获取方式其实取决于这个字段在你的业务逻辑中是**“必填字段”**还是**“可选字段”**。通常分为以下几种主流写法：

### 1. 可选字段：最常用 `value(key, default)`
如果字段可以不存在，且不存在时用一个默认值就能解决问题，`value()` 是绝对的主流。

```cpp
// 如果没有配置超时时间，默认给 30 秒
int timeout = config_json.value("timeout", 30);

// 如果没有配置名字，默认给空字符串（注意：必须是 std::string）
std::string name = config_json.value("name", std::string("")); 
```
**为什么常用：** 一行代码搞定，不用写 `if` 判断，不用 `try-catch`，代码极其干净。

---

### 2. 必填字段：最常用 `at(key).get<T>()` 或直接 `get<T>()`
如果这个字段是核心业务必须提供的（比如解析登录接口返回的 `user_id`），如果没有程序就没法往下走。这时最常用的是**直接取值并抛出异常**。

```cpp
// 方式 A：使用 at()
int user_id = root.at("uid").get<int>(); 

// 方式 B：使用 operator[]
int user_id = root["uid"].get<int>(); 
```
**为什么常用：** 
很多人有疑问，这跟我们上面说的安全性不矛盾吗？其实不矛盾。
* **`at()` 的优势：** 如果键不存在，`at()` 会抛出异常，但它**不会修改原 JSON 对象**（不会像 `operator[]` 那样塞入一个 `null`）。所以在日常开发中，老手更偏爱 `at()` 而不是 `operator[]`。
* **快速失败原则：** 既然是必填字段，如果缺失，说明上游传错了数据。此时直接抛出异常导致当前请求失败，比给一个默认的 `0` 继续往下跑要安全得多，能尽早暴露 Bug。

通常这种写法会包在一个大的 `try-catch` 块里，或者由最外层的 Web 框架统一捕获异常并返回 `400 Bad Request`。

---

### 3. 不可信的复杂结构：最常用 `contains()` 提前判断

如果 JSON 结构比较深，或者来源非常不可信，直接写 `root["a"]["b"]["c"].get<int>()` 是很危险的（中间某一层如果是 `null` 就崩了）。日常开发中最稳妥的写法是用 `contains()` 检查：

```cpp
if (root.contains("data") && root["data"].is_object()) {
    auto& data = root["data"];
    if (data.contains("user") && data["user"].is_object()) {
        auto& user = data["user"];
        if (user.contains("uid") && user["uid"].is_number()) {
            int uid = user["uid"].get<int>();
        }
    }
}
```
**为什么常用：** 虽然代码略显啰嗦，但在处理外部第三方 API 返回的复杂且不稳定的 JSON 时，这种写法能保证程序 100% 不崩溃。实际开发中，大家通常会封装一些辅助函数来简化这种嵌套判断。

---

### 总结：日常开发的最佳实践选型指南

| 场景                   | 字段重要性 | 推荐的日常写法                | 缺失时的行为                   |
| :--------------------- | :--------- | :---------------------------- | :----------------------------- |
| **读取配置文件**       | 可选       | `json.value("key", default)`  | 返回默认值，程序继续           |
| **读取 API 核心数据**  | 必填       | `json.at("key").get<T>()`     | 抛异常，中断当前逻辑，上报错误 |
| **读取不可信外部数据** | 不确定     | `json.contains("key")` 先判断 | 走 `else` 分支，记录日志       |

**一句话建议：** 
日常写业务代码时，优先用 `json.value("key", default)` 搞定非关键数据；遇到核心必填数据，用 `json.at("key").get<T>()` 让它直接报错。尽量避免使用 `json["key"].get<T>()`（即未加判断的 `operator[]`），以防不知不觉中修改了 JSON 对象。
