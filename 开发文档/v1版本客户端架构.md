## 1. 摘要

v1 客户端是一个 Qt Widgets 桌面聊天程序，已经完成：

```text
启动
  → 登录/注册/重置密码
  → HTTP 认证
  → TCP 聊天登录
  → 好友搜索
  → 好友申请/认证
  → 联系人和会话列表
  → 在线文本消息
```

客户端复用两个通道：

- HTTP：请求验证码、注册、登录、重置密码。
- TCP：登录聊天服务、好友业务和实时消息。

当前版本是 QML 重构前的稳定 Widgets 基线。

## 8. HTTP 层

### 8.1 HttpMgr

`HttpMgr` 是单例 `QObject`，持有 `QNetworkAccessManager`。

接口：

```cpp
void PostHttpReq(
    QUrl url,
    QJsonObject json,
    ReqId req_id,
    Modules mod);
```

### 8.2 请求

- Content-Type：`application/json`
- Transfer Timeout：10 秒
- 使用 Qt 默认异步请求。

### 8.3 响应分发

```text
QNetworkReply::finished
  → 检查 reply->error()
  → 成功：读取 JSON
  → sig_http_finish
  → 根据 Modules 分发
```

模块：

```text
MOD_REGISTER
MOD_RESET
MOD_LOGIN
```

### 8.4 页面回调表

每个页面内部维护：

```cpp
QMap<ReqId, std::function<void(const QJsonObject&)>> _handlers;
```

收到 HTTP 结果后先 `find(id)`，未知 ID 只提示错误，不调用空函数。

### 8.5 HTTP 接口

| ReqId | 路径 | 页面 |
| --- | --- | --- |
| 1001 | `/get_verifycode` | 注册/重置 |
| 1002 | `/user_register` | 注册 |
| 1003 | `/reset_pwd` | 重置 |
| 1004 | `/user_login` | 登录 |

## 9. 登录与进入聊天

```text
LoginDialog
  → 校验邮箱/密码
  → HTTP /user_login
  → 得到 uid/token/host/port
  → TcpMgr::slot_tcp_connect
  → QTcpSocket connected
  → 发送 1005 {uid, token}
  → 接收 1006
  → UserMgr 设置用户、Token、好友和申请
  → MainWindow 创建 ChatDialog
```

登录超时：

```text
发送 1005 后 10 秒
```

超时后恢复登录按钮。

## 10. TCP 层

### 10.1 TcpMgr 职责

- 保存 host/port。
- 建立 QTcpSocket。
- 发送帧。
- 接收 buffered 字节。
- 处理半包和粘包。
- 根据消息 ID 分发处理器。
- 管理登录定时器。
- 发出连接成功、失败、登录失败和断线信号。

### 10.2 状态

```text
Disconnected
  → Connecting
  → Connected
  → Disconnected
```

`_b_connected` 区分“连接成功后的断线”和“首次连接失败”。

## 11. TCP 协议

### 11.1 帧

```text
2 字节消息 ID
2 字节 JSON 长度
N 字节 UTF-8 JSON
```

约束：

```text
N <= 2048
```

### 11.2 发送

```text
sig_send_data(reqId, data)
  → 检查 socket 已连接
  → 检查 data.size <= 2048
  → QDataStream BigEndian 写头
  → append JSON
  → socket.write
```

### 11.3 接收状态机

```text
readyRead
  → buffer.append
  → 如果还没有头：
      需要 >= 4 字节
      读取 id/len
      移除头
  → 如果 buffer < len：
      标记 pending 并等待下一次 readyRead
  → buffer >= len：
      截取 body
      移除 body
      调用 handleMsg
```

### 11.4 消息表

| ID | 方向 | 作用 |
| --- | --- | --- |
| 1005 / 1006 | 发/收 | TCP 登录 |
| 1007 / 1008 | 发/收 | 搜索用户 |
| 1009 / 1010 | 发/收 | 好友申请 |
| 1011 | 收 | 好友申请通知 |
| 1013 / 1014 | 发/收 | 好友认证 |
| 1015 | 收 | 好友认证通知 |
| 1017 / 1018 | 发/收 | 文本消息 |
| 1019 | 收 | 文本消息通知 |

## 12. 文本消息分批

### 12.1 ChatProtocol

常量：

```cpp
MaxTextPayloadBytes = 2048
```

每次追加消息时计算完整请求：

```json
{
  "to_uid": 1002,
  "text_array": [
    {
      "unique_id": "...",
      "content": "..."
    }
  ]
}
```

### 12.2 三种结果

| 结果 | 行为 |
| --- | --- |
| `Appended` | 加入当前批次 |
| `NeedNewBatch` | 先发送当前批次，再开始新批次 |
| `TooLarge` | 单条消息过大，不发送 |

### 12.3 关键约束

- 按最终 JSON 紧凑序列化字节数计算。
- 中文和 emoji 不按字符数估算。
- 不切断单条消息内容。
- 单条超限时弹窗提示。

## 13. 字符输入限制

`CustomizeEdit` 当前按 grapheme 边界截断：

```text
QTextBoundaryFinder::Grapheme
```

避免：

- UTF-8 中文字节被切断。
- emoji 代理对被切断。
- 组合 emoji 被破坏。

`_max_len` 的语义因此是“用户可见字符簇数量”，不是 UTF-8 字节数，也不是严格的 UTF-16 code unit 数。

## 20. 断线与错误处理

### 20.1 HTTP

- 10 秒超时。
- 网络错误转为 `ERR_NETWORK`。
- JSON 解析失败提示。
- 未知响应 ID 不调用空回调。

### 20.2 TCP

- 发送前检查连接状态。
- 发送前检查 2048 字节。
- 未知消息 ID 记录日志。
- 登录超时 10 秒。
- 已连接后的断开触发 `sig_conn_lost`。
- ChatDialog 提示用户并禁用聊天页。

### 20.3 当前恢复能力

没有自动恢复：

- 不重连 TCP。
- 不重新申请 Token。
- 不回到登录页。
- 不恢复未发送消息。

## 22. 线程模型

客户端大部分逻辑运行在 Qt 主线程：

- HTTP reply 回调。
- QTcpSocket readyRead。
- UI 更新。
- UserMgr 状态修改。

优点：

- 不需要在客户端业务层频繁加锁。
- 信号槽默认 Direct/Queued 行为直观。

风险：

- 大量列表和消息渲染可能阻塞 UI。
- 历史消息增长后需要模型分页和延迟渲染。

## 24. 当前架构问题

| 问题 | 影响 |
| --- | --- |
| Dialog 动态创建 | 生命周期和信号连接分散 |
| UI 直连网络层 | 难以单测和 QML 复用 |
| UserMgr 职责过多 | 状态边界不清 |
| QListWidget + ItemWidget | 大量列表项性能有限 |
| 状态数据多份副本 | 容易不同步 |
| 无 ViewModel | QML 无法直接复用 |
| QSS 债务 | 视觉和状态规则不统一 |
| 无本地存储 | 重启丢失聊天 |
| 无心跳重连 | 弱网恢复能力弱 |

## 28. 完整端到端流程

本节从客户端视角串联启动、认证、好友和聊天流程，重点说明信号和内存状态如何变化。

### 28.1 应用启动完整流程

```text
main()
  → QApplication
  → 从 qrc 打开 style_sheet.qss
  → setStyleSheet
  → 读取 applicationDirPath()/config.ini
  → gate_url_prefix = http://host:port
  → 创建 MainWindow
  → 创建 LoginDialog
  → setCentralWidget(LoginDialog)
  → QCoreApplication::exec()
```

启动阶段没有 TCP 连接，也没有 UserMgr 用户信息。

失败情况：

- QSS 打开失败：仍启动，但无全局样式。
- config 缺失：Gate 地址为空，HTTP 请求失败。

### 28.2 注册完整流程

```text
RegisterDialog 输入邮箱
  → 校验邮箱格式
  → HttpMgr.PostHttpReq(/get_verifycode)
  → 收 sig_reg_mod_finish(1001)
  → ID_GET_VERIFY_CODE handler
  → 启动验证码倒计时

填写 user/passwd/confirm/verifycode
  → 本地校验
  → HttpMgr.PostHttpReq(/user_register)
  → 收 sig_reg_mod_finish(1002)
  → 检查 JSON/error
  → 显示注册成功
  → ChangeTipPage
```

注册成功后不自动登录，等待返回 LoginDialog。

### 28.2.1 重置密码完整流程

```text
LoginDialog 点击忘记密码
  → MainWindow 创建 ResetDialog
  → 输入邮箱并获取验证码
  → POST /reset_pwd
      {user,email,passwd,verifycode}
  → 收 sig_reset_mod_finish(1003)
  → ID_RESET_PWD handler
  → 检查 error
  → 显示重置成功
  → 用户返回 LoginDialog
  → 使用新密码重新登录
```

客户端不保存新密码，也不在本地修改旧 Token；旧 Token 的生命周期由服务端处理。

### 28.3 登录与进入聊天完整流程

```text
LoginDialog
  → 校验 email/passwd
  → enableBtn(false)
  → HTTP /user_login
  → 收 login JSON
  → 保存 _uid/_token
  → emit sig_connect_tcp
  → TcpMgr.slot_tcp_connect
  → QTcpSocket.connectToHost
  → connected
  → sig_conn_success(true)
  → LoginDialog 发送 1005
  → 启动 10 秒登录定时器
  → ChatServer 返回 1006
  → TcpMgr 处理用户、Token、好友、申请
  → emit sig_switch_chatDlg
  → MainWindow 创建 ChatDialog
  → ChatDialog 从 UserMgr 创建真实聊天和联系人列表
```

内存变化：

```text
UserMgr._user_info
UserMgr._token
UserMgr._apply_list
UserMgr._friend_list
UserMgr._friend_map
```

TCP 登录失败：

- 1006 error 非 0：`sig_login_failed`。
- 10 秒无 1006：`sig_login_timeout`。
- LoginDialog 恢复按钮并显示错误。

### 28.4 HTTP 登录超时和聊天登录超时的区别

两个超时不是同一个：

| 超时 | 层 | 时长 | 何时启动 |
| --- | --- | --- | --- |
| HTTP 传输超时 | QNetworkAccessManager | 10 秒 | 每个 HTTP 请求 |
| TCP 聊天登录超时 | TcpMgr 定时器 | 10 秒 | 发送 1005 后 |

HTTP 超时表示 GateServer 未及时返回。

TCP 登录超时表示 TCP 已连接但未收到 1006。

### 28.5 用户搜索完整流程

```text
SearchList 输入变化
  → 本地节流/搜索逻辑
  → 1007 {uid: input}
  → TcpMgr 等待 1008
  → ID_SEARCH_USER_RSP
  → JSON error 检查
  → 构造 SearchInfo
  → emit sig_user_search
  → FindSuccessDlg / FindFailDlg
```

当前搜索输入既可以表示 UID，也可以表示用户名，最终解释由服务端决定。

### 28.6 好友申请完整流程

```text
FindSuccessDlg
  → 打开 ApplyFriend
  → 填写申请信息/备注
  → 发送 1009
      {applyname,backname,to_uid}
  → ChatServer 持久化申请
  → 1009 的 1010 回包
```

被申请人如果在线：

```text
ChatServer
  → 1011
  → TcpMgr.sig_friend_apply
  → ChatDialog.slot_apply_friend
  → UserMgr.AddApplyList
  → UpdateApplyRedPoint
  → ApplyFriendPage.AddNewApply
```

申请只添加一次，`UserMgr::AlreadyApply` 避免重复插入同一 UID。

### 28.7 好友认证完整流程

```text
ApplyFriendPage 点击申请
  → AuthenFriend
  → 填写备注
  → 发送 1013 {to_uid,back}
  → ChatServer 事务完成好友关系
  → 1014 回包
  → TcpMgr.sig_auth_rsp
  → UserMgr.AddFriend
  → ChatDialog.slot_auth_rsp
  → MarkApplyHandled
  → UpdateApplyRedPoint
  → 创建 ChatUserWid
```

对方收到认证通知时：

```text
1015
  → TcpMgr.sig_add_auth_friend
  → UserMgr.AddFriend
  → ChatDialog.slot_add_auth_friend
  → 创建 ChatUserWid
```

### 28.8 文本消息发送完整流程

```text
ChatPage 点击发送
  → 检查 _user_info
  → MessageTextEdit.getMsgList()
  → 遍历 text/image
  → text:
      生成 QUuid
      obj={unique_id,content}
      ChatProtocol.TryAppendText
      如果 NeedNewBatch：先发送上一批
      如果 TooLarge：提示并跳过
  → 每批最多 2048 字节 JSON
  → 显示本地 TextBubble
  → emit sig_append_send_chat_msg
  → ChatDialog 更新 ChatUserWid 最后消息
  → UserMgr.AppendFriendChatMsg
  → TcpMgr.slot_send_data(1017)
  → 检查 connected 和 2048
  → 写 4 字节头 + JSON
```

本地消息先显示，不代表服务器持久化完成。

### 28.9 文本消息接收完整流程

```text
ChatServer 推送 1019
  → TcpMgr.readyRead
  → 拆帧
  → ID_NOTIFY_TEXT_CHAT_MSG_REQ handler
  → 构造 TextChatMsg
  → emit sig_text_chat_msg
  → ChatDialog.slot_text_chat_msg
  → 查找发送者

聊天列表已有发送者：
  → ChatUserWid.updateLastMsg
  → 更新最后消息
  → 若正在与发送者聊天，ChatPage 追加气泡
  → UserMgr 追加聊天消息

聊天列表没有发送者：
  → UserMgr.GetFriendById
  → 存在：创建 ChatUserWid
  → 更新最后消息
  → 插入列表首项
  → 不存在：记录警告并丢弃
```

### 28.10 客户端侧同服/跨服消息差异

客户端不需要区分消息是同服还是跨服：

```text
发送时始终 1017
接收时始终 1019
```

差异完全由 ChatServer 和 gRPC 处理。

客户端只需要关注：

- `unique_id`
- `content`
- `from_uid`
- `to_uid`

### 28.11 页面切换和状态保持

```text
LoginDialog → RegisterDialog
RegisterDialog → LoginDialog

LoginDialog → ResetDialog
ResetDialog → LoginDialog

LoginDialog → ChatDialog
```

当前切换由 `MainWindow` 动态创建和设置中心控件。

聊天页面创建后：

- 连接 TcpMgr 的好友、认证、聊天信号。
- 使用 UserMgr 已有好友和申请初始化列表。
- 从当前好友消息列表恢复当前进程内的聊天内容。

### 28.12 TCP 断线完整流程

```text
socket disconnected
  → 停止登录定时器
  → 清空接收缓冲
  → 清除半包状态
  → _b_connected=false
  → emit sig_conn_lost
  → ChatDialog.slot_conn_lost
  → 显示断线提示
  → 禁用聊天页
```

不会：

- 自动重连。
- 重新发送 1005。
- 返回登录页。
- 清理 UserMgr 好友和消息。

### 28.13 一次完整用户操作流

```text
启动客户端
  → 登录 HTTP
  → 建立 TCP
  → 1005 聊天登录
  → 加载好友/申请
  → 搜索并申请好友
  → 对方认证
  → 发送 1017
  → 本地气泡
  → 对方 1019
  → 双方更新最后消息
  → 断线提示
  → 当前 v1 结束
```

这条流程覆盖 v1 客户端从进程启动到聊天结束的全部关键状态变化。
