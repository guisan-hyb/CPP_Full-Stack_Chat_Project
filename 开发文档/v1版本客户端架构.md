# v1 版本客户端架构

## 1. 文档定位

本文总结 v1 Qt Widgets 客户端的实际实现，作为后续 QML 重构前的基线。

v1 客户端覆盖：

- 登录。
- 注册。
- 重置密码。
- TCP 聊天登录。
- 用户搜索。
- 好友申请。
- 好友认证。
- 联系人列表。
- 在线文本聊天。
- 用户资料展示。

v1 不包含：

- 聊天记录持久化。
- 离线消息。
- 心跳。
- 自动重连。
- 踢人。
- 完整图片和文件消息协议。
- QML UI。

## 2. 技术栈

| 模块 | 技术 |
| --- | --- |
| UI | Qt Widgets、`.ui`、自定义 QWidget |
| 网络 | Qt Network、QTcpSocket、QNetworkAccessManager |
| JSON | QJsonObject、QJsonArray、QJsonDocument |
| 样式 | QSS |
| 构建 | qmake |
| C++ | C++17 |

当前使用 Qt 6.11 MSVC 2022 x64。

## 3. 客户端分层

```text
UI 层
  MainWindow / LoginDialog / RegisterDialog / ResetDialog
  ChatDialog / ChatPage / ContactUserList / ApplyFriend 等
        ↓
全局状态与视图管理
  UserMgr / UserInfo / FriendInfo / ApplyInfo / TextChatData
        ↓
网络层
  HttpMgr / TcpMgr / ChatProtocol
        ↓
GateServer HTTP / ChatServer TCP
```

当前 UI 和状态层仍有一定耦合，QML 重构时重点是拆出 ViewModel。

## 4. 启动与页面切换

入口：

```text
client/main.cpp
```

启动过程：

```text
创建 QApplication
  → 加载 qrc 中的 style_sheet.qss
  → 从 config.ini 读取 GateServer 地址
  → 创建 MainWindow
  → 默认显示 LoginDialog
```

`MainWindow` 负责：

- 登录、注册、重置密码页面切换。
- TCP 登录成功后创建 ChatDialog。

当前页面切换仍通过动态创建 Dialog 和 `setCentralWidget` 完成，后续可改为 `QStackedWidget` 或 QML StackLayout。

## 5. HTTP 层

### 5.1 HttpMgr

`HttpMgr` 使用 `QNetworkAccessManager` 发送 POST JSON。

接口：

```cpp
void PostHttpReq(QUrl url, QJsonObject json, ReqId req_id, Modules mod);
```

设置：

```text
Content-Type: application/json
传输超时: 10 秒
```

结果通过信号分发：

```text
sig_reg_mod_finish
sig_reset_mod_finish
sig_login_mod_finish
```

### 5.2 HTTP 接口

| 客户端操作 | HTTP 路径 |
| --- | --- |
| 获取验证码 | `/get_verifycode` |
| 注册 | `/user_register` |
| 登录 | `/user_login` |
| 重置密码 | `/reset_pwd` |

各对话框通过 `_handlers` 映射处理响应。

响应 ID 使用 `find()` 判空，未知 ID 不会调用空回调。

## 6. TCP 层

### 6.1 TcpMgr

`TcpMgr` 使用单例管理一个 `QTcpSocket`。

职责：

- 连接 ChatServer。
- 发送 TCP 帧。
- 拆分半包和粘包。
- 根据消息 ID 分发处理器。
- 保存登录超时定时器。
- 通知连接成功、失败和断开。

### 6.2 帧格式

```text
2 字节消息 ID（大端）
2 字节消息体长度（大端）
N 字节 JSON
```

客户端发送前约束：

```text
N <= 2048
```

`TcpMgr::slot_send_data` 会检查：

- Socket 是否已连接。
- 序列化消息体是否超过 2048 字节。

### 6.3 接收处理

```text
readyRead
  → 追加接收缓冲
  → 读取 4 字节帧头
  → 等待完整消息体
  → 提取 JSON
  → 根据消息 ID 分发
```

未注册的消息 ID 只记录日志，不崩溃。

### 6.4 登录超时

发送 1005 TCP 登录后启动 10 秒定时器。

收到 1006 登录响应后停止。

超时后通知登录界面并恢复按钮。

## 7. 客户端消息 ID

| ID | 作用 |
| --- | --- |
| 1005 / 1006 | TCP 登录请求/响应 |
| 1007 / 1008 | 用户搜索请求/响应 |
| 1009 / 1010 | 好友申请请求/响应 |
| 1011 | 好友申请通知 |
| 1013 / 1014 | 好友认证请求/响应 |
| 1015 | 好友认证通知 |
| 1017 / 1018 | 文本消息请求/响应 |
| 1019 | 文本消息通知 |

## 8. ChatProtocol

新增：

```text
client/chatprotocol.h
client/chatprotocol.cpp
```

主要接口：

```cpp
QByteArray BuildTextRequest(int to_uid, const QJsonArray& messages);
AppendResult TryAppendText(int to_uid, QJsonArray& batch, const QJsonObject& message);
```

分批结果：

```text
Appended
NeedNewBatch
TooLarge
```

规则：

- 根据最终 JSON 字节数判断。
- 只在完整消息对象之间分批。
- 不切断单条 `content`。
- 单条超过 2048 字节时提示用户，不发送。

客户端不再使用请求体中的 `from_uid` 作为身份；发送者由服务端 Session 决定。

## 9. 全局状态

### 9.1 UserMgr

`UserMgr` 是客户端单例状态容器，保存：

```text
_user_info
_token
_apply_list
_friend_list
_friend_map
聊天列表已加载计数
联系人列表已加载计数
```

数据结构：

| 类型 | 作用 |
| --- | --- |
| `UserInfo` | 当前用户或聊天页面用户视图 |
| `FriendInfo` | 好友、备注、最后消息和消息列表 |
| `ApplyInfo` | 好友申请 |
| `TextChatData` | 单条文本消息 |
| `TextChatMsg` | 一组接收到的文本消息 |

当前聊天记录只保存在内存中，软件重启后丢失。

### 9.2 好友和联系人分页

客户端批量读取内存中的好友：

```text
每页 13 条
聊天列表和联系人列表分别维护已加载数量
```

尚未连接服务端分页接口。

## 10. 聊天界面

### 10.1 ChatDialog

聊天主界面包括：

- 左侧栏。
- 聊天列表。
- 联系人列表。
- 搜索列表。
- 聊天页。
- 好友申请页。
- 好友资料页。

主要职责：

- 同步好友申请和认证通知。
- 切换聊天联系人。
- 维护聊天列表条目。
- 将发送和接收消息交给 ChatPage 与 UserMgr。

### 10.2 ChatPage

负责：

- 显示当前好友。
- 加载内存聊天记录。
- 消息气泡渲染。
- 输入内容分组发送。

v1 已删除随机模拟聊天用户，列表只显示真实好友。

### 10.3 消息气泡

消息组件：

```text
ChatItemBase
  → TextBubble / PictureBubble
  → BubbleFrame
  → MessageTextEdit
```

文本消息支持基础富文本和图片缩略展示。

当前网络主链路只发送文本消息。

## 11. 输入和字符边界

`CustomizeEdit` 用于限制输入长度。

字符截断使用：

```text
QTextBoundaryFinder::Grapheme
```

避免切断：

- 中文。
- emoji。
- 组合 emoji。
- 组合附加字符。

## 12. 错误与断线处理

v1 已处理：

- HTTP 10 秒超时。
- 未知响应 ID。
- JSON 解析失败。
- 空指针。
- 未知发送者。
- TCP 发送前连接状态检查。
- TCP 断线提示。

断线后显示“聊天服务器连接已断开”，并禁止当前聊天页面继续操作。

v1 不自动重连，也不会自动清理当前聊天内存。

## 16. 当前架构债务

- UI 和业务逻辑仍较集中。
- `UserMgr` 同时承担当前用户、好友、申请和聊天状态。
- 聊天列表使用 `QListWidget + setItemWidget`，数据量增长后性能有限。
- 页面切换会动态创建 Dialog。
- QSS 有重复和失效规则。
- 尚未使用 `QAbstractItemModel`。
- 没有 ViewModel 层。
- 没有心跳、重连和本地消息缓存。

## 17. QML 重构方向

推荐保持 C++ 网络与状态层，逐步创建 QML v2：

```text
QML Views
  ↓
QObject ViewModel / QAbstractListModel
  ↓
HttpMgr / TcpMgr / UserStore
```

迁移顺序：

1. 登录、注册、重置密码。
2. ChatShell 和会话列表。
3. 联系人和好友申请。
4. 文本聊天。
5. 富文本、图片和文件编辑。
6. 统一 Theme 和组件库。

## 18. v1 结论

v1 客户端已经形成完整的桌面聊天交互闭环，具备 HTTP 认证、TCP 长连接、好友关系、在线文本消息、明确错误处理和 2048 字节协议边界。

下一阶段应先完成心跳、重连和会话生命周期，再启动 QML ViewModel 与界面重构。
