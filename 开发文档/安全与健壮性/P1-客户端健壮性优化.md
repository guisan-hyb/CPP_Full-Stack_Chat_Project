# P1 客户端健壮性优化

## 1. 文档目标

本文记录 Qt Widgets 客户端在 QML 重构前的 P1 健壮性修复，包括：

- UTF-8 与 emoji 安全截断。
- 2048 字节 TCP JSON 包边界。
- HTTP 请求超时。
- 未知响应 ID 防护。
- 删除客户端测试假数据。
- 空指针保护。
- TCP 断线提示。

本轮不新增心跳、自动重连或踢人功能，这些留到后续版本。

## 2. UTF-8 安全截断

### 2.1 原问题

`CustomizeEdit` 原来按 UTF-8 字节截断：

```cpp
QByteArray byteArray = text.toUtf8();
byteArray = byteArray.left(_max_len);
setText(QString::fromUtf8(byteArray));
```

UTF-8 中一个中文字符通常占 3 字节，emoji 可能占 4 字节或更多 UTF-16 单元。按字节截断可能产生半个字符。

### 2.2 新实现

新增：

```text
client/textutils.h
```

使用 `QTextBoundaryFinder::Grapheme` 按用户可见字符边界截断：

```cpp
QTextBoundaryFinder finder(QTextBoundaryFinder::Grapheme, text);
```

这样可以避免截断：

- 中文。
- emoji。
- 组合 emoji。
- 组合附加符号。

`CustomizeEdit` 使用 `QSignalBlocker`，避免 `setText` 再次递归触发 `textChanged`。

## 3. 2048 字节消息边界

### 3.1 协议约定

服务端帧体上限：

```text
2048 字节
```

服务端接收逻辑：

```text
2 字节消息 ID
2 字节消息长度
N 字节 JSON 消息体
```

其中 `N <= 2048`。

客户端原来按 1024 个 QString 字符累积，和 2048 字节完全不是同一单位。

例如：

```text
1024 个中文字符
≈ 3072 个 UTF-8 字节
```

即使字符数没有超过 1024，序列化后仍可能超过服务端上限。

### 3.2 ChatProtocol

新增：

```text
client/chatprotocol.h
client/chatprotocol.cpp
```

常量：

```cpp
constexpr int MaxTextPayloadBytes = 2048;
```

构造请求：

```cpp
QJsonObject request;
request["to_uid"] = to_uid;
request["text_array"] = messages;
return QJsonDocument(request).toJson(QJsonDocument::Compact);
```

追加消息使用：

```cpp
ChatProtocol::TryAppendText(...)
```

返回结果：

```text
Appended     当前消息可以加入现有批次
NeedNewBatch 当前批次已满，应先发送再开新批次
TooLarge     单条消息本身已超过 2048 字节
```

### 3.3 分片规则

消息只在完整 JSON 消息对象之间分批：

```text
{text_array: [消息1, 消息2, 消息3]}
```

不会把某条消息的 `content` 从中间切开。

单个正常消息保持：

```text
unique_id
content
```

完整。

如果单条消息本身超过 2048 字节：

1. 不进入网络发送队列。
2. 不显示为已发送本地气泡。
3. 弹出“消息过长”提示。

### 3.4 TcpMgr 最后防线

`TcpMgr::slot_send_data` 发送前再次检查：

```cpp
if (dataBytes.size() > 2048) {
    qWarning() << "TCP payload exceeds 2048 bytes";
    return;
}
```

避免 `quint16` 强转导致长度字段与实际包体不一致。

同时检查 Socket 是否已连接，未连接时不写数据。

## 4. HTTP 超时

### 4.1 原问题

`QNetworkRequest` 没有传输超时。GateServer 或网络异常时，登录、注册、重置密码按钮可能长期保持禁用。

### 4.2 新实现

`HttpMgr::PostHttpReq` 增加：

```cpp
request.setTransferTimeout(10000);
```

超时后 Qt 会结束请求并进入现有网络错误回调，界面随后恢复按钮状态并显示网络错误提示。

## 5. 未知 HTTP 响应 ID

### 5.1 原问题

三个对话框使用：

```cpp
_handlers[id](jsonObj);
```

`QMap::operator[]` 在 key 不存在时会插入空的 `std::function`，随后调用会崩溃。

### 5.2 新实现

登录、注册、重置密码统一改为：

```cpp
auto handler = _handlers.find(id);
if (handler == _handlers.end()) {
    qWarning() << "response has no handler:" << id;
    showTip(tr("未知服务器响应"), false);
    return;
}
handler.value()(jsonObj);
```

未知 ID 不再触发空函数调用。

## 6. 删除测试假数据

删除：

- 聊天列表启动时插入的 13 条随机用户。
- 联系人列表启动时插入的 13 条随机联系人。
- 聊天页面中的 `test_rc` 测试数据容器。

现在列表只使用 `UserMgr` 中的真实好友数据。

搜索申请头像仍使用本地资源随机占位，这属于现有资源缺失时的展示逻辑，不是伪造好友或申请数据。

## 7. 空指针保护

增加保护的位置：

- `ChatUserWid::SetInfo(UserInfo)`
- `ChatUserWid::SetInfo(FriendInfo)`
- `ChatUserWid::updateLastMsg`
- `ChatPage::SetUserInfo`
- `ChatPage::AppendChatMsg`
- 好友申请通知
- 好友认证回调
- 搜索跳转
- 好友信息页跳转
- 发送消息通知
- 收到文本消息

特别是收到未知发送者消息时：

```cpp
auto fi_ptr = UserMgr::GetInstance()->GetFriendById(msg->_from_uid);
if (!fi_ptr) {
    qWarning() << "message sender is not in friend list";
    return;
}
```

不会再向 `ChatUserWid::SetInfo()` 传入空指针。

## 8. TCP 断线提示

### 8.1 TcpMgr

新增状态：

```cpp
bool _b_connected;
```

新增信号：

```cpp
void sig_conn_lost();
```

连接成功时设置：

```text
_b_connected = true
```

断线时：

- 停止登录超时定时器。
- 清空接收缓冲。
- 清理半包状态。
- 重置消息 ID 和长度。
- 只有确实连接成功过，才发送 `sig_conn_lost()`。

### 8.2 ChatDialog

聊天界面连接 `sig_conn_lost`：

```text
显示“聊天服务器连接已断开”
禁用当前聊天页面操作
```

当前版本不会自动重连，也不会自动切回登录页。

## 9. 测试

新增：

```text
client/tests/client_protocol_test.cpp
client/tests/client_protocol_test.pro
```

测试内容：

1. 中英文和 emoji 混合文本按用户可见字符截断。
2. 两条消息合并超过 2048 字节时返回 `NeedNewBatch`。
3. 追加失败不会修改当前批次。
4. 已生成 JSON 不超过 2048 字节。
5. 单条超大消息返回 `TooLarge`。
6. 超大消息不会部分加入批次。

测试结果：

```text
client protocol tests passed
```

Qt 客户端完整构建通过。

## 10. 当前边界

本轮没有实现：

- 心跳。
- 自动重连。
- 断线后恢复登录状态。
- 消息发送队列持久化。
- 图片和文件消息网络协议。
- 踢人。
- QML UI 重构。

这些属于后续客户端架构迭代或新功能版本。
