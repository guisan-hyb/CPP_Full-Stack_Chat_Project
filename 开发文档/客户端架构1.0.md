## 2. 注册验证码获取时序图（动态交互流程）

```mermaid
sequenceDiagram
    participant User as 用户
    participant RegisterDialog as 注册对话框
    participant HttpMgr as HTTP管理器
    participant Server as 后端服务

    User->>RegisterDialog: 点击“获取验证码”
    RegisterDialog->>RegisterDialog: 校验邮箱格式
    alt 格式正确
        RegisterDialog->>HttpMgr: PostHttpReq( url=/get_verifycode, json={email} )
        HttpMgr->>Server: HTTP POST 请求
        Server-->>HttpMgr: 返回 JSON 响应
        HttpMgr-->>RegisterDialog: sig_reg_mod_finish( id, res, err )
        RegisterDialog->>RegisterDialog: 解析 JSON，根据 ReqId 调用回调
        alt 服务器返回成功
            RegisterDialog-->>User: 显示“验证码已发送”
        else 服务器返回错误
            RegisterDialog-->>User: 显示错误提示
        end
    else 格式错误
        RegisterDialog-->>User: 提示“邮箱地址不正确”
    end
```

## 3. 架构特点简述（配合图示）

- **界面层**：`MainWindow` 作为容器，管理 `LoginDialog` 和 `RegisterDialog` 的切换，二者均设为无边框窗口。
- **业务逻辑层**：`RegisterDialog` 内部维护 `_handlers` 映射表，将请求 ID（`ReqId`）与回调函数绑定，实现响应处理的可扩展性；通过信号槽与 `HttpMgr` 通信。
- **网络层**：`HttpMgr` 采用线程安全的单例模式，封装 `QNetworkAccessManager`，统一处理 POST 请求，并通过模块标识（`Modules`）将响应分发给对应的对话框。
- **基础设施**：
  - `global.h` 提供全局枚举、变量和工具函数（如 `repolish`）。
  - `singleton.h` 提供可复用的单例模板。
  - 配置文件 `config.ini` 在 `main()` 中被读取，动态构建 `gate_url_prefix`。
  - 样式表 `style_sheet.qss` 在启动时加载，配合 `repolish` 实现动态样式刷新。
