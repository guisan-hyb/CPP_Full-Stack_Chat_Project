# v1 版本客户端架构与流程

## 0. 文档说明

### 0.1 定位

本文以当前 Qt Widgets 客户端为实现基线，整理架构、关系拓扑、局部流程和完整端到端流程。

参考分析框架：

- `客户端架构2.0.md`：类职责、UI 树、TCP 状态机、消息渲染链。
- `全栈架构与处理流程3.0.md`：客户端到服务端的整体调用链。
- `P0-Session身份校验与好友消息授权.md`：身份字段变化。
- `P1-客户端健壮性优化.md`：UTF-8、2048 字节、HTTP 超时和断线处理。

### 0.2 v1 目标

```text
登录/注册/重置密码
  → HTTP 认证
  → TCP 聊天登录
  → 好友搜索/申请/认证
  → 联系人列表
  → 在线文本消息
```

### 0.3 技术栈

| 能力 | 技术 |
| --- | --- |
| UI | Qt Widgets、`.ui` |
| 样式 | QSS、动态属性 |
| HTTP | QNetworkAccessManager |
| TCP | QTcpSocket |
| JSON | QJsonObject/Array/Document |
| 构建 | qmake |
| 平台 | Windows、Qt 6.11、MSVC 2022 x64 |

## 4. HTTP 架构

### 4.1 架构关系

```mermaid
graph LR
    Dialog["Login/Register/Reset"]
    Http["HttpMgr"]
    Reply["QNetworkReply"]
    Module["Module Signals"]
    Handler["Dialog _handlers"]
    Gate["GateServer HTTP"]

    Dialog -->|PostHttpReq| Http
    Http -->|POST JSON| Gate
    Gate --> Reply
    Reply --> Http
    Http -->|sig_http_finish| Module
    Module -->|sig_*_mod_finish| Dialog
    Dialog --> Handler
```

### 4.2 请求

```cpp
PostHttpReq(url, json, req_id, mod);
```

参数：

| 参数 | 含义 |
| --- | --- |
| `url` | GateServer 完整 URL |
| `json` | 请求 JSON |
| `req_id` | 具体操作 ID |
| `mod` | 注册/重置/登录模块 |

### 4.3 配置

- Content-Type：`application/json`
- 超时：10 秒
- 异步完成，不阻塞 UI 线程

### 4.4 模块分发

| Module | 信号 | 页面 |
| --- | --- | --- |
| `MOD_REGISTER` | `sig_reg_mod_finish` | RegisterDialog |
| `MOD_RESET` | `sig_reset_mod_finish` | ResetDialog |
| `MOD_LOGIN` | `sig_login_mod_finish` | LoginDialog |

### 4.5 回调表

每个 Dialog 维护：

```cpp
QMap<ReqId, std::function<void(const QJsonObject&)>> _handlers;
```

使用 `find()` 判断未知 ID，避免调用空函数。

## 5. TCP 架构

### 5.1 连接状态机

```mermaid
stateDiagram-v2
    [*] --> Disconnected
    Disconnected --> Connecting: connectToHost
    Connecting --> Connected: connected
    Connecting --> Disconnected: error
    Connected --> Disconnected: disconnected/error
```

### 5.2 帧格式

```text
+----------------+----------------+----------------------+
| msg_id (2B BE) | len (2B BE)    | JSON body (len B)    |
+----------------+----------------+----------------------+
```

约束：

```text
len <= 2048
```

### 5.3 接收解析

```mermaid
flowchart TD
    A["readyRead"] --> B["append _buffer"]
    B --> C{"need header?"}
    C -- yes --> D{"buffer >= 4?"}
    D -- no --> R["return wait"]
    D -- yes --> E["read msg_id/msg_len"]
    E --> F["remove 4-byte header"]
    C -- no --> G
    F --> G{"buffer >= msg_len?"}
    G -- no --> H["_b_recv_pending=true"]
    H --> R
    G -- yes --> I["extract body"]
    I --> J["remove body"]
    J --> K["handleMsg(id, body)"]
    K --> L{"buffer has more?"}
    L -- yes --> C
    L -- no --> R
```

### 5.4 分发

```text
msg_id → _handlers[msg_id]
```

未知 ID 记录日志并丢弃，不影响后续包。

### 5.5 发送保护

发送前检查：

- Socket 是否 Connected。
- payload 是否超过 2048 字节。

## 6. ChatProtocol

### 6.1 接口

```cpp
QByteArray BuildTextRequest(int to_uid, const QJsonArray& messages);
AppendResult TryAppendText(int to_uid, QJsonArray& batch, const QJsonObject& message);
```

### 6.2 结果

| 结果 | 含义 |
| --- | --- |
| `Appended` | 当前批次可加入 |
| `NeedNewBatch` | 当前批次已满 |
| `TooLarge` | 单条消息本身超过 2048 |

### 6.3 分批原则

- 按最终紧凑 JSON 字节数。
- 不按 QString 字符数估算。
- 只在完整消息对象之间拆分。
- 单条消息内容不拆开。

### 7.2 主要 DTO

| 类型 | 主要字段 |
| --- | --- |
| `UserInfo` | uid/name/nick/icon/sex/last_msg/chat_msgs |
| `FriendInfo` | uid/name/nick/icon/sex/desc/back/last_msg/chat_msgs |
| `ApplyInfo` | uid/name/nick/icon/sex/desc/status |
| `TextChatData` | unique_id/content/from_uid/to_uid |
| `TextChatMsg` | from_uid/to_uid/message array |

### 7.3 数据权威性

当前聊天状态不是单一模型：

```text
UserMgr._friend_map
ChatUserWid._user_info
ChatPage._user_info
```

三者共享部分 `shared_ptr`，但容器可能各自追加消息。v1 能工作，但后续 QML 应改为唯一 Store。

## 9. 完整端到端流程

### 9.1 主流程时序

```mermaid
sequenceDiagram
    autonumber
    participant U as User
    participant L as LoginDialog
    participant H as HttpMgr
    participant G as GateServer
    participant T as TcpMgr
    participant C as ChatServer
    participant M as MainWindow
    participant D as ChatDialog

    U->>L: email/password
    L->>H: /user_login
    H->>G: HTTP
    G-->>H: host/port/token
    H-->>L: response
    L->>T: connect
    T->>C: TCP connect
    T->>C: 1005
    C-->>T: 1006
    T->>M: sig_switch_chatDlg
    M->>D: create ChatDialog
    D->>D: load friends/apply lists

    U->>D: search/add/auth
    D->>T: 1007/1009/1013
    T->>C: TCP
    C-->>T: responses/notifications

    U->>D: send text
    D->>D: 2048-byte batching + bubble
    D->>T: 1017
    T->>C: TCP
    C-->>T: 1018/1019
    T->>D: update list/chat

    C--xT: disconnect
    T->>D: sig_conn_lost
```

### 9.2 阶段说明

#### 阶段一：认证

```text
LoginDialog
  → HttpMgr
  → GateServer
  → uid/host/port/token
```

#### 阶段二：聊天会话

```text
TcpMgr
  → ChatServer
  → 1005/1006
  → UserMgr 登录态
  → ChatDialog
```

#### 阶段三：好友

```text
搜索
  → 申请
  → 通知
  → 认证
  → 好友列表更新
```

#### 阶段四：在线聊天

```text
MessageTextEdit
  → ChatProtocol
  → 1017
  → ChatServer
  → 1019
  → ChatDialog/ChatPage
```

#### 阶段五：断线

```text
socket disconnected
  → sig_conn_lost
  → warning
  → 聊天页禁用
```

### 9.3 客户端状态变化总表

| 阶段 | UI | UserMgr | TcpMgr |
| --- | --- | --- | --- |
| HTTP 登录前 | Login | 空 | Disconnected |
| HTTP 登录成功 | 等待 TCP | 可暂存 uid/token | Connecting |
| TCP 连接成功 | 等待 1006 | — | Connected |
| TCP 登录成功 | ChatDialog | 用户/好友/申请 | Connected |
| 好友申请 | 申请页/红点 | 追加申请 | Connected |
| 好友认证 | 聊天/联系人 | 追加好友 | Connected |
| 发送消息 | 本地气泡 | 追加聊天 | Connected |
| 接收消息 | 更新列表/气泡 | 追加聊天 | Connected |
| 断线 | 提示并禁用 | 保留内存状态 | Disconnected |

## 13. 当前风险和架构债务

| 类别 | 问题 |
| --- | --- |
| 页面生命周期 | 每次切换动态创建 Dialog |
| UI 解耦 | View 直接调用网络层和 UserMgr |
| 状态一致性 | 好友消息存在多份视图容器 |
| 列表性能 | QListWidget + setItemWidget |
| 消息持久化 | 仅内存 |
| 网络恢复 | 无心跳、无重连 |

| 测试 | UI 和状态层缺自动化测试 |
